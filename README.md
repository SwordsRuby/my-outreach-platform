# Проект: Внутренняя платформа аутрич-агентства

## Описание

Данный проект представляет собой веб-приложение на **Next.js (App Router)** с использованием **TypeScript** и **PostgreSQL** для работы с данными компаний. Реализованы:

- Загрузка данных из JSON-файлов (~1000 компаний).
- Загрузка и анализ дополнительного CSV-файла (`review.csv`) с выявлением аномалий.
- Страница `/companies` с поиском по названию и фильтром по городу.
- Три аналитических SQL-запроса для агрегации данных.

Проект разрабатывался с использованием AI-инструментов (DeepSeek-V3, GPT-5.5) и повторяет реальные задачи интеграции данных в аутрич-агентстве.

## Установка и настройка

### 1. Клонирование репозитория

```bash
git clone my-outreach-platform
cd my-outreach-platform
```

### 2. Установка зависимостей

```bash
npm install
```

Дополнительные пакеты (уже добавлены в `package.json`):
- `pg` – работа с PostgreSQL
- `dotenv` – управление переменными окружения
- `csv-parser` – парсинг CSV
- `ts-node` / `tsx` – запуск TypeScript-скриптов

### 3. Настройка переменных окружения

Создайте файл `.env` в корне проекта на основе `.env.example`:

```bash
cp .env.example .env
```

Отредактируйте `.env`, указав строку подключения к вашей базе данных PostgreSQL:

```
DATABASE_URL=postgresql://user:password@localhost:5432/mydb
```

### 4. Создание базы данных и пользователя

Если вы не создавали базу, выполните команды (замените `myuser`, `mypassword`, `mydb` на свои):

```bash
sudo -u postgres psql -c "CREATE USER myuser WITH PASSWORD 'mypassword';"
sudo -u postgres psql -c "CREATE DATABASE mydb OWNER myuser;"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE mydb TO myuser;"
```

### 5. Применение схемы

В файле `sql/schema.sql` описана структура таблицы `companies` и индексы. Примените её:

```bash
psql $DATABASE_URL -f sql/schema.sql
```

Если расширение `pg_trgm` не установлено, выполните:

```bash
sudo -u postgres psql -d mydb -c "CREATE EXTENSION IF NOT EXISTS pg_trgm;"
```

Затем повторно создайте индекс по названию (если не создался):

```bash
sudo -u postgres psql -d mydb -c "CREATE INDEX IF NOT EXISTS idx_companies_name ON companies USING GIN (name gin_trgm_ops);"
```

## Загрузка данных

### Подготовка файлов

Скопируйте все файлы из архива `data_pack.zip` в папку `data/` в корне проекта:

```
data/
├── page_001.json
├── page_002.json
├── ...
├── page_020.json
└── review.csv
```

### Загрузка JSON-данных

```bash
npm run load-json
```

Скрипт прочитает все 20 JSON-файлов и загрузит записи в таблицу `companies`. В случае совпадения `id` записи будут обновлены.

### Загрузка и анализ review.csv

```bash
npm run load-csv
```

Скрипт:
- Загружает данные из `review.csv`.
- Проверяет наличие `id`, валидность рейтинга, количества отзывов, телефона, сайта.
- Обновляет или добавляет записи в таблицу `companies`.
- Формирует отчёт `ANOMALIES.md` со всеми найденными аномалиями.

## SQL-запросы (аналитика)

В файле `sql/queries.sql` содержатся три аналитических запроса:

### 1. Топ-5 категорий по числу компаний

```sql
SELECT category, COUNT(*) AS company_count
FROM companies
GROUP BY category
ORDER BY company_count DESC
LIMIT 5;
```

**Пример результата** (после загрузки всех данных):

| category | company_count |
|----------|---------------|
| Оптовая торговля | 87 |
| IT-интегратор    | 76 |
| Стоматология      | 65 |
| Рекламное агентство | 62 |
| Медицинский центр | 58 |

### 2. Средний рейтинг по городам (компании с 10+ отзывами)

```sql
SELECT city, ROUND(AVG(rating)::NUMERIC, 2) AS avg_rating
FROM companies
WHERE reviews_count >= 10
  AND rating IS NOT NULL
GROUP BY city
ORDER BY avg_rating DESC;
```

**Пример результата** (первые строки):

| city | avg_rating |
|------|------------|
| Москва | 4.68 |
| Санкт-Петербург | 4.55 |
| Казань | 4.49 |
| ... | ... |

### 3. Доля компаний с сайтом по категориям

```sql
SELECT
    category,
    COUNT(*) AS total,
    COUNT(site) AS with_site,
    ROUND((COUNT(site)::NUMERIC / COUNT(*)) * 100, 2) AS site_percentage
FROM companies
GROUP BY category
ORDER BY site_percentage DESC;
```

**Пример результата**:

| category | total | with_site | site_percentage |
|----------|-------|-----------|-----------------|
| IT-интегратор | 76 | 62 | 81.58 |
| Рекламное агентство | 62 | 48 | 77.42 |
| ... | ... | ... | ... |

Все запросы можно выполнить через `psql`:

```bash
psql $DATABASE_URL -f sql/queries.sql
```

## Обнаруженные аномалии (ANOMALIES.md)

При загрузке `review.csv` было выявлено **206 аномалий**. Основные типы:

### 1. Отсутствие id в основной таблице (≈ 190 записей)

Большинство записей в `review.csv` имеют идентификаторы, которых нет в таблице `companies`. Это ожидаемо, так как `review.csv` – это «свежая выгрузка» из другой системы, содержащая новые компании или удалённые из основного справочника.

Пример:
```
id "c_001005" не найден в таблице companies
```

### 2. Некорректные значения рейтинга

- Отрицательный рейтинг: `c_001122` → `-3`
- Рейтинг выше 5: `c_001186` → `7.2`

### 3. Отрицательное количество отзывов

- `c_001116` → `-10`

### 4. Проблемы с телефоном

- `c_001004` → `8 (925) abc-12-34` (содержит буквы)
- `c_001091` → `+7` (слишком короткий)

### 5. Некорректный сайт

- `c_001064` → `нет сайта` (вместо URL)
- `c_001020` → `htp://sintez-service-453.ru` (опечатка в протоколе)

### 6. Пустые строки в CSV

В конце файла обнаружены две пустые строки без данных.

### 7. **Проблема с кодировкой (Windows-1251)**

При загрузке `review.csv` были обнаружены города с искажёнными символами, например:
- `РЎР°РЅРєС‚-РџРµС‚РµСЂР±СѓСЂРі` (вместо `Санкт-Петербург`)
- `РњРѕСЃРєРІР°` (вместо `Москва`)

Это произошло из-за того, что файл был сохранён в кодировке Windows-1251, а скрипт читал его как UTF-8. Для исправления были выполнены SQL-запросы вида:

```sql
UPDATE companies SET city = 'Санкт-Петербург' WHERE city = 'РЎР°РЅРєС‚-РџРµС‚РµСЂР±СѓСЂРі';
UPDATE companies SET city = 'Москва' WHERE city = 'РњРѕСЃРєРІР°';
-- и так далее для всех искажённых названий
```

Чтобы избежать этого в будущем, при чтении CSV необходимо указывать правильную кодировку, например, с помощью пакета `iconv-lite`.

Полный список аномалий доступен в файле `ANOMALIES.md`.

## Проверка работоспособности

После запуска приложения я выполнил следующие проверки:

1. **Загрузка JSON**: убедился, что все 20 файлов прочитаны, количество записей в БД ~1000.
2. **Загрузка CSV**: скрипт отработал, создан `ANOMALIES.md`, количество записей увеличилось до ~1190.
3. **Страница `/companies`**:
   - Открыл страницу – увидел таблицу с компаниями.
   - Ввёл в поиск «Оптовая» – отфильтровались только компании с этим словом в названии.
   - Выбрал в фильтре «Москва» – таблица обновилась, показаны только компании из Москвы.
   - Совместил поиск и фильтр – работает корректно.
   - Убедился, что рейтинг отображается звёздами, а `null` – как «—».
   - Проверил, что при пустом поиске и фильтре отображается полный список (с лимитом 100 записей).
4. **SQL-запросы**: выполнил все три запроса, получил осмысленные результаты (примеры приведены выше).
5. **Аномалии**: нашёл проблемы с кодировкой, исправил их через UPDATE.

В процессе разработки возникла ошибка с `rating.toFixed is not a function` – исправлено добавлением преобразования строки в число.
